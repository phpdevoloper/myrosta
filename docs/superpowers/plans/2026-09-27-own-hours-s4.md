# Own hours on a booking (S4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a clinical booking carry its own start and finish when they differ from its shift type's window, set by the admin from the cell editor and — when the group's switch is on — by staff at booking and afterwards, with pay, the calendar, reminders, the digest and the safe-hours rules all reading the same hours.

**Architecture:** One reader carries the behaviour: `shiftWindow(cyc,sh)` → `{start,end,own}` answers "when does this shift run" from the booking's own `hours:{start,end}` when present and valid, else from the type's window. Every reader of a shift's times in the app goes through it, and both Edge Functions gain the same three lines as `hoursOf(sh,ty)`. `hoursOK` says what may be stored (HH:MM, 5-minute steps, finish after start or 00:00 for midnight, never across midnight), `hoursNorm` returns the object to store or `null` when it is the type's own window, and `hoursSet` is the one guarded write for staff (admins write through the cell editor's Save). Cover, the unlock order, quota, fairness, the S3 judge and the on-call layer keep reading the type and the half.

**Tech Stack:** Single-file vanilla JS app (`app.html`), tests under JavaScriptCore via `osascript` (`python3 tests/run.py`), Python lints in `tests/run.py`, the demo built by `tools/build-demo.py`; two Edge Functions in the repo (`supabase/functions/ics/index.js`, `supabase/functions/notify-shifts/index.ts`) whose pure blocks the suite lifts and runs. No SQL.

**Spec:** `docs/superpowers/specs/2026-09-26-own-hours-s4-design.md` (read it first; this plan argues from it). Programme: `docs/superpowers/specs/2026-09-16-staff-group-modules-programme.md`.

## Global Constraints

- **No own hours means no change.** A booking without `hours` reads exactly as today: `shiftHours`, `shTimeStr`, the payroll rows, the RosterOn cell, the roster CSV and Excel, the calendar download and feed, the reminder, the digest and every screen are byte for byte what they were. `normalize()` seeds nothing; `S.ownHours` is absent until an admin ticks the switch, and is **deleted** (never written as `false`) when unticked. Every existing test passes unchanged.
- **Hours on the booking, and only a clinical one.** `hours:{start:"HH:MM",end:"HH:MM"}` is stored only when `hoursOK` accepts the pair and it differs from the type's window (`hoursNorm`); the key is deleted when cleared or when it comes to equal the type's. Never on CST, leave or on-call. An unknown or malformed pair reads as the type's window everywhere.
- **`hoursOK(start,end)`:** both `HH:MM` (00–23, 00–59), minutes a multiple of 5, `end` after `start`, or `end==="00:00"` with `start` later than midnight. Nothing else is stored, by the app or by the import.
- **The reader takes its cycle explicitly** (`shiftWindow(cyc,sh)`), like the S3 judge, so the digest and an off-screen cycle get the same answer. `_shiftSpan`'s on-call extension is unchanged; only its base window may come from the booking.
- **Cover, unlock, quota, fairness, the S3 judge and the on-call layer read the type and the half, never the hours.** The safe-hours rules read the real hours: a staff change that breaks a rest rule is refused in block mode with the reason and warned in warn mode, exactly like a booking. Changing hours is not coming off, so the notice period does not apply.
- **Who may set hours:** an admin from the cell editor on any day (past days included); staff only when `S.ownHours===true`, on their own booking, on a live roster, on a day not yet passed. Every refusal names its reason.
- **Audit and notifications:** every `logAudit` call passes its key as a **string literal first argument** and every key has an `AUDIT_WORDS` sentence. New keys: `hours.set`, `hours.clear`, `settings.ownHours`. When staff set or clear hours the admin is told ("Jo Park changed their hours on Tue 29 Sep to 09:30–15:00."); when an admin sets someone else's through `hoursSet` that person is told. The cell editor's Save writes `hours.set`/`hours.clear` only when the times changed.
- **The Edge Functions** gain `hoursOf(sh,ty)` with the same rule as the app; nothing calls notify-shifts; the owner pastes both after the build is live (Task 6's deploy note).
- **The lints stay green:** `tab_wiring_lint` (every `data-…` control drawn by `daySheetHTML`/`dsBookedActs` is wired inside `if(S.tab==="selfroster"){`), `pick_key_lint` (the literals `canBook(sid,a[0],a[1],a[2],a[3])` and `pickCheck(_srSid||S.viewAs,a[0],a[1],a[2],a[3])` stay in the file), `audit_words_lint`, `build_lint`, the css lints (no hex, no px font sizes, tokens only), `deploy_lint`, `demo_lint`.
- Copy: plain words, sentence case, no emoji or arrow glyphs inside buttons, notes or tags. Every name is rendered through `escapeHTML`. Test dates are relative to today (`iso(addDays(new Date(),n))`); never hardcode a future date.
- `deploy/demo.html` must equal what `python3 tools/build-demo.py` produces from the current `app.html` (a lint checks this), so run the build before the tests in every task; `deploy/app.html` and `preview.html` are synced with `$SP/sync.py` in every task (a lint checks them too).
- `tests/oncall-golden.js` must pass unchanged and is **never regenerated** to make a test pass.
- SWIFT's files in `~/Desktop/Myrosta site 2/` hold personal data and never enter the repo.
- Commit on `main`; do not push (the owner pushes from GitHub Desktop).

## Decisions this plan takes where the spec is silent or over-specified

1. **With the switch on, a pick keeps the day sheet open** instead of closing it, so the Hours row (which appears once the day has a pick) is right there under the chips; *Done* closes the sheet. With the switch off the sheet closes on a pick, exactly as today.
2. **Hours at booking belong to the basket.** They are held in `_srHours[isoD]` beside the pick, written on Confirm through `canBook(sid,isoD,p,zoneId,typeId,hours)` (a sixth, optional argument: the safe-hours rules judge the real hours at booking, and `_fatigueWarn` behaves as today), and dropped whenever that day's pick changes or the basket is dropped. The snake draft's book-one-per-turn path has no Hours row; staff set hours afterwards with *Change hours*.
3. **`srHoursFor(cyc,isoD,p,typeId)`** is the one reading of what was typed beside a pick: `{ok:true,hours:null}` when nothing or the type's own window was typed, `{ok:true,hours:{start,end}}` when a different valid pair was, `{ok:false,reason}` when the pair is not allowed — that pick then fails on Confirm with the reason, and the other picks land.
4. **The cell editor's Hours row is read at Save from the draft.** Typing into Start or Finish stores the raw pair on `modal.draft.hours` (a new object, never a mutation of the stored booking); *Same as the type* deletes it; a change of type or period deletes it; Save deletes it when both are empty or equal the type's window, refuses with `fieldError` when the pair is not allowed, and otherwise stores the normalised pair. The prefill is `modalHours(draft,cyc)` — own hours when the draft has them, else the type's window.
5. **`hoursSet(sid,isoD,start,end)`** is the staff write (a guarded write, judged again inside it, busy key `"hr-"+sid+"|"+isoD`); an empty pair clears. The inline *Change hours* form keeps what was typed when a save is refused, like a call-in. Admins are allowed through it too (past days included) so the suite can drive every branch, but the cell editor stays their way in.
6. **Every reader appends the window only when it is the booking's own**, through `ownHoursTag(cyc,sh)` → `" 09:30–15:00"` or `""`: the roster CSV and Excel labels, the Day board rows, the mobile week list and the swap text. The grid cell shows a small second line. The day sheet says "09:30–15:00 (own hours)" in place of "starts 10:00".
7. **An offer's snapshot carries the hours** (`swShiftOf` copies them when valid) so the swap text can say them; `swSame` still compares period, zone and type only, so a change of hours does not make a standing offer read as "changed". A give-away's claimer inherits the giver's hours (`_osExecute`); an open shift posted from a gap has none. Swap approval already exchanges the whole bookings, hours included.
8. **The import** keeps a cell's `HHMM-HHMM` as `start`/`end` on the parsed entry, and `importShift(cyc,sh)` stores them as own hours when `hoursOK` accepts them and they differ from the window of the type the booking lands on; a pair the rule refuses (across midnight, say) is dropped and the type's window stands.
9. **The Edge Functions' `hoursOf`** mirrors `hoursOK` exactly (format, steps, order, midnight), so the three readers agree on valid and malformed data alike.
10. **The release note is dated 27 Sep 2026.** If the release ships on another day, change `2026-09-27` in `WHATS_NEW`, `const BUILD` and the changelog heading together (a lint keeps them equal).

## How to edit `app.html`, `tests/suite.js`, the Edge Functions and the docs

`app.html` is one large file with very long lines, and much of its script writes characters as JavaScript escapes (a backslash, `u`, four hex digits). Tool parameters can silently turn those escapes into the characters themselves, so an exact-match edit then fails, or writes the wrong thing. Make every edit through this helper, and write each such escape as `@U@` followed by the four hex digits (`@U@2019` for a right single quote, `@U@2014` for an em dash, `@U@2013` for an en dash, `@U@00b7` for a middle dot, `@U@2192` for an arrow). The helper turns `@U@` back into the escape in both the text it looks for and the text it writes. Anchors in this plan avoid the file's literal non-ASCII characters wherever a shorter ASCII anchor is unique.

- [ ] **Create the helpers once**, in your scratchpad directory (called `$SP` below):

```python
# file: rep.py
# $SP/rep.py  —  usage: python3 $SP/rep.py <file to edit> <edits file>
import pathlib, sys
BS = chr(92)
target = pathlib.Path(sys.argv[1]); text = [target.read_text(encoding="utf-8")]; n = [0]
def fix(t): return t.replace("@U@", BS + "u")
def rep(old, new, cnt=1):
    old = fix(old); new = fix(new); c = text[0].count(old)
    if c != cnt: sys.exit("expected %d, found %d: %r" % (cnt, c, old[:160]))
    text[0] = text[0].replace(old, new); n[0] += 1
exec(open(sys.argv[2], encoding="utf-8").read())
target.write_text(text[0], encoding="utf-8"); print("replacements:", n[0])
```

Myrosta — multi-org isolation test

v4 — every probe is non-destructive, so it can run against staging, a rehearsal clone, or production at cutover. Proves a member of one organisation is denied another organisation's data by the database itself (RLS) — regardless of what any app code does. Nothing here touches production.

1 · Project

your org + an org you are NOT a member of (staging: test-orgA / test-orgB)

2 · Sign in as a test user

Sign in as User A (member of org A only) and run. Then sign out, sign in as User B, run again. Optionally User AB (both orgs) to see the memberships list return two rows.

Password sign-in avoids the staging email limits (create the users under Authentication → Users with "Auto confirm"). Email code also works if you prefer:
Not signed in.

3 · Run the probes

Each probe expects the database to deny the other org and allow your own.
ProbeExpectResultDetail

Any FAIL = do not ship multi-org. Re-run after any RLS change.
